Scoring model

        
The project separates raw dimensions from persona weighting so the same tool can rank differently for CISO, AppSec, Red Team, MLOps, PM, startup builder, agent architect, or MCP security reviewer.

      

    

    

    

      Persona score formula
      persona_score = weighted_average(selected_dimension_scores, persona_weights) × 20
      
Raw dimensions use a 1–5 scale. Persona score is normalized to 0–100 for easier comparison.

    

    

      Agentic Readiness Score
      

      
Use this score when selecting tools for autonomous agents, multi-step workflows, tool execution, delegated tasks, or production agent runtime control.

    

    

      MCP Security Score
      

      
Use this score when reviewing MCP clients, third-party MCP servers, tool permissions, server inventory, tool output sanitization, sandboxing, and MCP supply-chain exposure.

      

    

  




  

    

      

        
Scoring methodology and evidence model

        
Scores are not certifications. They are transparent, community-maintained heuristics designed to help reviewers create shortlists and identify evidence gaps.

      

    

    

    

      Recommended evidence policy
      
Prefer conservative scoring. Increase scores only when the tool has explicit product documentation, open-source implementation evidence, OWASP landscape inclusion, reproducible community verification, or a submitted benchmark result.

    

    

      Evidence confidence score
      
confidence = OWASP landscape + vendor docs + benchmark-backed evidence + community review + incident mapping - staleness penalty. Tool cards and detail pages expose this score to distinguish validated claims from inferred mappings.

    

    

      ASI coverage depth
      
0 = no coverage · 1 = inferred · 2 = explicit / OWASP or vendor-public claim · 3 = benchmark-backed or implementation-verified. This prevents a flat risk tag from looking stronger than the evidence supports.

    

    

      Lifecycle coverage scoring
      
0 = no mapped coverage · 1 = inferred / indirect · 2 = vendor-public claim · 3 = OWASP landscape + vendor docs · 4 = community-tested · 5 = benchmark-backed

    

  



  

    

      

        
Solution & Tool Validation Agent

        
A deterministic rule-based agent for turning an agentic AI scenario into OWASP ASI risk mapping, recommended security stack, evidence checks, and benchmark validation plan.

      

    

    

      

        
1. Parse scenario

        
Reads a scenario JSON describing frameworks, MCP/A2A/tool use, RAG or memory, external APIs, high-impact actions, and deployment constraints.

      

      

        
2. Map OWASP ASI risks

        
Maps architecture signals to ASI01–ASI10 using explicit deterministic rules, not model-generated scores.

      

      

        
3. Recommend tools

        
Ranks tools by risk coverage, lifecycle fit, framework support, deployment constraints, Agentic Readiness, MCP Security, and evidence confidence.

      

      

        
4. Validate evidence

        
Checks whether each recommended tool has OWASP landscape, vendor-public, community, or benchmark-backed evidence.

      

      

        
5. Plan benchmark execution

        
Selects MCP/A2A benchmark cases from benchmarks/mcp_security_benchmark_v01.json and produces score update suggestions.

      

      

        
Run locally

        
python agents/solution_validator_agent.py --scenario examples/mcp_rag_agent_scenario.json --output outputs/mcp_rag_agent_solution_report.md

      

    

  



  

    

      

        
Grounded LLM Q&A Agent

        
An optional LLM-assisted Q&A layer that retrieves from data/source_index.json first, then forces indexed source citations such as [S001] to reduce hallucinated tool claims, scores, and OWASP mappings.

      

    

    

      

        
1. Build source index

        
python agents/build_source_index.py --output data/source_index.json

      

      

        
2. Ask offline

        
python agents/grounded_qa_agent.py --question "Which tools should I evaluate for MCP runtime security?" --provider none

      

      

        
3. Ask with LLM

        
OPENAI_API_KEY=... python agents/grounded_qa_agent.py --question "Design a validation plan" --provider openai-compatible --model gpt-4o-mini --fallback-on-uncited

      

      

        
4. Citation audit

        
The CLI checks whether cited source IDs were retrieved. If the LLM gives uncited or unsupported output, use --fallback-on-uncited to return an extractive answer instead.

How to update and maintain

    

      

        
1. Add or edit a tool

        
Edit data/tools.json. Keep each score between 1 and 5 and add a short maintainer_notes field explaining caveats.

      

      

        
2. Map Agentic OWASP / ASI

        
Add agentic_owasp, lifecycle_stages, agentic_scores, and mcp_scores. Prefer conservative scoring unless the tool has evidence for runtime enforcement, MCP coverage, agent identity controls, or specific OWASP lifecycle support.

      

      

        
3. Add evidence or benchmark results

        
Add supporting records to data/evidence.json. For MCP / A2A tests, add or update cases in benchmarks/mcp_security_benchmark_v01.jsonl and attach runner output from benchmarks/results/.

      

      

        
4. Validate before commit

        
Run a JSON parse check and validate against data/schema.json, then open index.html locally. The included GitHub Action validates schema, ASI codes, score ranges, duplicate IDs, and Hugging Face metadata.

      

      

        
5. Deploy to Hugging Face

        
Create a Hugging Face Space, choose Static SDK, and commit README.md, index.html, styles.css, app.js, and data/tools.json.
